# Red Flags & Rationalization Table — matching-and-augmenting-resume

Bulletproofing。重读 at every phase checkpoint,**尤其 Phase 3 选择题挖掘 + Phase 4 学习推荐**(本 skill 两个最易翻车的点)。

---

## User-Side Red Flags

| Signal | Issue | Response |
|---|---|---|
| "我感觉我这岗位完全够不上" | 自我贬低(常见学生 pattern) | "数据说话。我们走完 Phase 2 看 priority score 再下结论。很多学生意外发现 priority 比想象高。" |
| 选择题答了"都没有 / E (没接触过)" 3 次 | 疲倦 / 真的没相关 | 第 3 次后停问这个维度,move on |
| "F 其他(填空)" 用户写得很模糊 | 不知道如何描述 | 给 1-2 个引导例子帮他具体化 |
| Phase 2 用户说"那我就只投 Priority 4+ 的吧" | 过度收窄 | "Priority 3 也值得投。你能投 5 份,就投 5 份。" |
| Phase 4 用户说"那我学不完" | 时间预算冲突 | "按时间预算分流不是'必须都学完',挑 1-2 个最高 leverage 的就好。" |

## Claude Self-Check

| Rationalization | Counter |
|---|---|
| "Phase 3 用户答得快,合并 2 题" | **不可商量** — 一 turn 一题,合并会让追问深度丢失 |
| "Phase 3 选择题选项写得难一点,显得专业" | **反向** — 选项要低门槛(沾边都算)。专业不在选项,在追问深度 |
| "Phase 4 学习资源越多越好" | **不要** — 学生会被淹没。每 gap 2-3 个资源足够 |
| "Phase 4 资源凭印象给,推荐书名" | **Anti-fabrication** — 只推荐你确定存在的(知名书/课程/官方文档)。不确定→描述内容方向让用户自己 Google |
| "Phase 2 priority score 给保守点" | **不要** — 实事求是。给保守 = 用户少投 = 失去机会 |
| "Phase 2 不足分析写细致,显得专业" | 不要过载。每个岗位列 5 个 top gap 就够,更多会让用户绝望 |
| "Phase 1 解析简历用户没补充就够用" | 读完后**必须读回 high-level 给用户确认**,避免理解错 |
| "Phase 5 直接 default handoff 给 bullet-writer" | **不行** — 必须问用户后续意图(5 选 1 多选),根据答案再 handoff |
| "用户疲倦了,提前结束 Phase 3" | OK,但**必须保留至少 2 个 augmented story 才进 Phase 4** — 否则白挖 |
| "学生说'我没经验'就接受 + 帮他写一个看起来像有的" | **拒绝 fabrication**。reframe 用 Phase 3 选择题挖掘,沾边的都算 |

## 终极红线(立刻 stop + restart 当前 phase)

- Phase 3 选择题没含 E "没接触过但感兴趣" 或 F 填空(把用户框死)
- Phase 3 用户选了某选项,**没追问深度问题** 就 move on
- Phase 4 推荐了 Claude 不确定存在的资源(凭空捏造书名/课程名)
- Phase 2 priority score 没有引用简历的**具体段**作为匹配证据
- Phase 5 没问用户后续意图就 default handoff
- 任何 phase 一 turn 问 2+ 个问题
- 空洞夸赞("great answer!" / "你简历挺强的!")
- 帮用户 fabricate 经验(把"听说过"写成"做过")

## Spirit vs Letter

**违反 letter 就是违反 spirit。**

本 skill 的 spirit 是:**用低摩擦方式把学生记不起来的、不当一回事的经验挖出来,匹配到岗位的具体诉求,提升初筛命中率**。每个 shortcut 都会回到一个 fail mode:学生填了一堆问卷但没挖到有效素材,或推了一堆资源学生根本不会看。

如果你想"这题不重要,跳过吧" — 那是反 spirit 的 rationalization。
