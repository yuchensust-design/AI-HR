# Multiple-Choice Question Design — Phase 3 Methodology

Phase 3 的"低门槛挖掘"靠选择题。这份文档详述选择题的**设计方法论 + 反模式**。

**核心原则**(图中提取):
- 让用户少打字 → 优先选择题
- 沾边都算 → 选项要 inclusive
- JD + 公司业务双维度 → 不只问 JD 关键词
- 留 1 个填空 → 不要把用户框死

---

## 标准模板

```
{引子:为什么问这个 — 跟岗位/公司有什么关系}

{核心问题}?(可多选)
A. {直接相关:做过这件事 / 系统学过}
B. {直接相关:另一种形式}
C. {间接相关:做过相关的、能 connect 的事}
D. {兴趣/学习相关:听过 / 关注过 / 想学}
E. 没有但很感兴趣,愿意快速学
F. 其他(填空)__________
```

**关键设计点**:
- A/B 是"硬证据"(明显能算 relevant experience)
- C 是"软证据"(沾边,需要少量包装)
- D 是"兴趣信号"(能解释 motivation,但不是 experience)
- E 是"虚心信号"(虚心愿意学,recruiter 看到也加分)
- F 兜底,避免框死用户

**用户多选,Claude 后续追问每个选中项的细节**。

## 示例 1:公司业务相关(图中给的音乐例)

**引子**:字节跳动这个目标岗位会涉及音乐相关业务(汽水音乐 / 抖音音乐 / 短视频 BGM)。

**问题**:你之前有以下哪种音乐相关经验?(可多选)
- A. 学过乐器 / 唱歌 / 系统的音乐课程
- B. 写过乐评 / 听音乐很投入 / 参加过音乐演出/活动
- C. 做过音乐相关的产品分析 / 用户研究 / 用户访谈
- D. 持续关注音乐行业新闻 / 了解音乐产业生态
- E. 没有但很感兴趣,愿意快速学
- F. 其他(填空)__________

**追问示例**(用户选 B):
> "你选了 B — 在哪里写的(豆瓣 / 公众号 / 自己 Notion)?写了几篇?哪一篇你印象最深、为什么?"

→ 用户回答后,写成 STAR 故事:
- Situation: 在 {平台} 维护乐评
- Task: 推荐/评论小众音乐 给目标听众
- Action: 写了 {N} 篇,平均每篇 {长度},涉及 {流派/主题}
- Result: {阅读量 / 互动 / 转发 / 反响},培养了对音乐产业内容/用户审美的敏感度

→ 这个故事进 augmented-storybank,跟 PM intern 的 JD 关键词"内容理解 / 用户审美 / 内容运营 sense"挂钩。

## 出题维度(优先级)

按 Phase 2 输出的 Cross-Job Gap Summary,优先出题维度:

1. **公司业务/行业相关**(图中明确强调)— 比 JD 关键词更容易被忽略,挖到的经验差异化最强
2. **JD 软技能关键词**(协作 / 沟通 / 领导力 / 抗压 / 创新 等)— 学生最容易没意识到
3. **JD 技术栈/工具**(具体技能)— 学生通常知道有但低估
4. **JD 行业域知识**(医疗 / 金融 / 教育 等)— 学生容易觉得"我没经验" actually 沾边的不少

每个维度 1-2 题,3-5 道题为上限,**不要超**(用户疲倦)。

---

## 反模式 — 不要这样设计

### ❌ 让人觉得在被审判的题
"你做过 {高规格成就} 吗?"(用户多半回答"没有",失去挖掘机会)
→ ✅ 应改:"以下哪种你做过或接触过?"(给低门槛选项)

### ❌ 选项写死、没留余地
"你的 LLM 经验是?A. 微调过模型 B. 部署过生产 C. 写过 paper"(都是高门槛)
→ ✅ 应改:加 D"看过教程 / 玩过 API",E"还没接触但想学",F 填空

### ❌ 一题问多个 gap
"你做过项目管理 / 跨团队 / 数据分析吗?"(混乱)
→ ✅ 应改:3 道独立的题,每题 1 个 gap

### ❌ 用 jargon 而不解释
"你会 RAG 吗?A. 会 B. 不会"(很多本科学生不知道 RAG 是啥)
→ ✅ 应改:"你做过让 AI 工具回答你提供的资料的项目吗?(俗称 RAG / 检索增强)"+ 后面给低门槛选项

### ❌ 没说"为什么问这个"
直接问"你做过音乐相关的事吗?"(用户懵)
→ ✅ 应改:加引子"这个公司主要做音乐内容,你做过...吗?"

---

## 选项数 / 题数控制

- **每题选项**: 4-6 个(含填空)
- **每个 gap**: 1-2 题
- **总题数**: ≤5 题(疲倦门槛)
- **答完一题就追问 1 个深度问题**,而不是一次问完所有题

---

## 追问深度问题的模板

用户选了某个选项后,统一格式:

> "你选了 {选项} — {针对该选项的具体细节问题}?"

例:
- A(学过乐器)→ "学的什么?学了多久?到什么程度?"
- B(写过乐评)→ "在哪里写的?写了几篇?哪一篇你印象最深?"
- C(做过用户研究)→ "什么时候做的?访谈了几个人?有什么意外发现?"
- D(关注行业)→ "你关注的方式是?最近一条记忆深刻的行业动态?"
- E(没有但感兴趣)→ "你怎么知道自己对这个感兴趣?可以投入多久去学?"
- F(填空)→ 用户自己写的,Claude 复述确认 + 深问 1 个
